<b>Цель:</b> сделать наблюдение интересно само по себе, а экспериментирование - понятным без знаний программирования.

## 1. Принципы дизайна

- <b>Мир на первом плане:</b> 60–70% рабочей области занимает сцена, панели контекстные.
- <b>Красиво, но достоверно:</b> анимация интерполирует симуляционные состояния; не добавляет фальшивых рождений, атак и «разумных» действий.
- <b>От обзора к причине:</b> сначала общая популяция, затем регион, затем конкретное существо/линия и история его решений.
- <b>Объяснимость:</b> каждая карта имеет единицы, легенду, диапазон и отметку интервенций.
- <b>Бережное внимание:</b> не бесконечный журнал каждого движения, а аналитически значимые события и возможность раскрыть детали.
- <b>Эксперименты не должны портить исходный мир:</b> создать fork сохранения перед изменением параметров.

## 3. Визуализация организмов

- <b>LOD0:</b> при отдалении цветные точки, цвет по наследуемой линии, размер по массе.
- <b>LOD1:</b> при среднем масштабе простые геометрические символы + heading + энергия.
- <b>LOD2:</b> при приближении выбранный организм, сенсорный радиус, направление движения, визуальный след последних 50–200 тиков (выключаемо).
- Переключатели окраски: lineage, genome trait, energy, age, predator/prey (когда появится), selected descendants.
- Движение интерполировать между snapshot кадрами (зафиксировать, что в UI реконструкция приблизительная, не влияет на tick).
- Тепловые карты: производимая пища, детрит, плотность, смертность/рождаемость, температура (после climate).
- Zoom/pan, select, follow, focus on region, screenshot, legend, accessibility contrast.

## 4. Инспектор существа

<code>OrganismInspector</code> должен отображать:

- id + lineage id + родитель + дата рождения + возраст/поколение;
- энергия (progress bar), текущие координаты и выбранное действие;
- таблица генов и сравнение с медианой популяции;
- phenotype-cost: сколько энергии тратится на движение и восприятие;
- количество потомков, ближайшие родственники;
- история значимых событий и причина смерти для deceased (из архива);
- граф предков на 2–5 уровней, потом - lazy loading lineage graph.

<b>Не показывать:</b> «уровень интеллекта 87» без операционного определения и проверки метрики.

## 5. Панель наблюдения за миром

Основные метрики (зависят от этапа):

- <code>alivePopulation</code>, <code>birthsPerWindow</code>, <code>deathsPerWindow</code>, <code>medianAge</code>, <code>foodBiomass</code>, <code>meanEnergy</code>;
- <code>geneticDiversity</code>, <code>lineageCount</code>, <code>resourceScarcityIndex</code>, <code>predationRate</code>;
- <code>TPS</code>, <code>renderFPS</code>, <code>tickDurationP95</code>, <code>memoryFootprint</code>.

Графики имеют понятные оси, доступные tooltips и выбор интервала. Разделить «симуляционные показатели» (изменяют понимание мира) и «системные показатели» (производительность приложения).

## 6. Лента событий и история

<b>Не писать событие на каждый tick каждого агента.</b> EventDetector агрегирует:

- вымирание линии (когда последняя особь исчезла);
- резкий рост/падение популяции за окно;
- ресурсный шок, засуха, внешняя интервенция;
- появление доминирующего генетического кластера;
- значимый скачок fitness proxy, особенно при контрольном сравнении;
- выбранный организм умер/размножился, если за ним следят.

Каждое событие содержит <code>eventId</code>, <code>tick</code>, <code>kind</code>, <code>subjectIds</code>, <code>region</code>, <code>metricsBefore</code>, <code>metricsAfter</code>, <code>causeHint</code>, <code>evidenceRefs</code>, <code>detectorVersion</code>. <code>causeHint</code> - <b>эвристическое объяснение</b>, не доказательство причинности. По клику - график/контекст.

## 7. Создание мира

Шаг 1: шаблон (Garden, Scarcity, Islands). Шаг 2: seed с кнопкой random / копировать. Шаг 3: базовые настройки: width/height, начальная популяция, мутации, плотность пищи, стоимость метаболизма. Шаг 4: «Создать».

Готовые пресеты должны быть красивыми и работоспособными без изменения настроек. «Advanced» скрыт по умолчанию, содержит подсказки единиц и диапазонов.

При изменении настроек в живом мире:

- «Новый мир» с новыми параметрами;
- «Сделать fork и применить интервенцию» - по умолчанию безопасное изменение;
- «Изменить в текущем мире» - с записью события и предупреждением, что сравнение до/после - не чистый эксперимент.

## 8. Состояния интерфейса

Empty (нет миров), Generating (seed/progress), Running, Paused, FastForward, Inspecting, Saving, Restoring, Error, ReadOnlyCompatibility (несовместимый snapshot). При Worker crash - показать diagnostic ID и выбор последнего валидного сохранения, а не белый экран.

Возможность отключать тяжёлые визуальные слои отдельно от симуляции. При ускорении 32× рендер должен автоматически снижать частоту обновления без потери реальных тиков.

## 9. Принципы визуальной идентичности

- Тёмная спокойная тема по умолчанию, «лаборатория + биолюминесцентный микромир».
- Фон земли/воды должен контрастировать с организмами; избегать слишком яркого неона всюду.
- Траектории и вспышки размножения - умеренные, отключаемые, масштабируются по LOD.
- Использовать собственные процедурные формы/шейдеры/иконки, без лицензионно сомнительных assets.
- Звуки необязательны: можно добавить генеративные ambient cues только после основных функций, с mute и без автоматического запуска.
- Поддержка EN/RU через string keys, в MVP как минимум единообразные русские подписи; i18n механизм не блокирует первую версию.

## 10. Критерии приёмки интерфейса

- За 60 секунд новый пользователь без документации запускает мир и находит паузу/ускорение.
- Можно открыть информацию о выбранном агенте, затем переключить режим карты и сохранить мир.
- Мировая симуляция продолжает работать при закрытых панелях и при замедленном рендере.
- При 5k организмов фронтенд не клонирует тысячи JS объектов при каждом render React.
- Keyboard: Space play/pause (когда фокус не в input), стрелки/+- навигация, Escape cancel selection.
- Скриншот визуально соответствует реальному состоянию на указанном tick (не фиктивные данные).
- Browser E2E: create, pause, step, inspect, save, restore, reload, export.
